# Bot間協調の設計

## 実装状況

Bot間メッセージ、委任、グループチャット、成果物APIは未実装である。
この文書のAPIや制限値は、現時点で利用可能な機能を表さない。
先にPiの実通信確認とVM接続管理を完了する。

## ハーネス非依存のAPI

協調の正本はPi Extension内ではなく、専用の管理サービスに置く。
Pi、Codex、OpenCodeなどは同じAPIのクライアントになる。
Bot自身が送信元IDを偽装できないよう、APIの資格情報からBot IDを導出する。

候補となる操作は `list_bots`、`send_message`、`delegate_task`、`get_task_status`、`complete_task`、`share_artifact` である。
Pi Extensionに公開するときは、実行先PiのExtension APIで定義する。
このMacの独自PiとSDK固定版のAPIを同一と仮定しない。

## 永続レコード

| レコード | 必要な情報 |
|---|---|
| Message | ID、送信元、宛先、group、本文、作成時刻、相関ID、配送状態 |
| Task | ID、依頼元、担当、parent、root、深度、状態、期限、成果物参照 |
| Artifact | ID、所有者、許可先、サイズ、digest、media type、保存先 |
| Group | ID、参加Bot、会話履歴、応答のルーティング規則 |

タスクの状態遷移と担当者による完了権限をサーバーで検証する。
Botの個別メモリをグループ参加だけで他Botへ開放しない。

## ループと重複実行の防止

委任にはroot taskのIDと経路を伝播させる。
同じBotを経路内へ再追加する委任を拒否する。
最大深度、task期限、Bot単位と全体の同時実行数を設定で制限する。
再送はidempotency keyで同じ操作へ収束させる。
具体的な既定値は実装前に確定する。

グループ発言は明示したメンション先、またはユーザーが選んだ担当だけへ配送する。
Bot発言を全Botの新規応答トリガーにはしない。
自動相談にはtaskの予算と終了条件を設ける。

## 成果物の受け渡し

VMをまたぐ共有ファイルシステムは必須にしない。
成果物をAPIへアップロードし、許可されたBotだけがIDで取得する。
パス指定による任意ファイル取得、path traversal、symlink経由の流出、サイズ無制限転送を拒否する。
送信と受信の双方でdigestを確認する。

機密の分類と読取権限は成果物レコードに保存する。
保存後に権限が変わる場合も、取得時点で認可する。
