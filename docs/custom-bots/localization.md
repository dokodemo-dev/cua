# 日本語表示の導入記録

## 方針

公式アプリとCua Botsに既存の言語パック機構がないため、共通の日英カタログと表示言語設定を追加した。
現在の会話で、両アプリと共有Web UIを対象に段階的に進める方針を確認した。
実モデルへの依頼文や会話履歴の言語を変える機能ではない。

実装と追加手順の正本は[`libs/cua-localization/README.md`](../../libs/cua-localization/README.md)に置く。
SwiftとWebでカタログを別々に持たず、同じJSONを参照する。
保存先は既存のBotデータやSDK設定とは分離し、RustのFFI型や生成バインディングは変更しない。

## 確認結果

- 共通Swiftパッケージのテストを通過した。
- Cua Botsの実行ファイルをビルドし、既存Coreテスト29件が成功した。
- 公式macOS版の実行ファイルをビルドし、Webブリッジと言語設定の41テストが成功した。
- Web UIの型検査と本番ビルドが成功した。
- Webのカタログ、言語選択、ホストアダプター、ブリッジ契約の関連テストが成功した。
- 一時HOMEのCua Botsで、英語への切り替え、日本語への切り替え、保存ファイルへの反映をGUIから確認した。
- 独立したブラウザーセッションで、Web UIの日英切り替え、再読み込み後の保持、`html`の`lang`属性、横方向にはみ出さないことを確認した。

Web全体のテストには、ファイル転送の表示文を期待する既存の失敗が1件ある。
`src/bridge/__tests__/detail.test.ts`の`a Space's drop well`で、`done: notes.txt`に検証結果の説明が付かない。
変更前のソースを一時ディレクトリへ展開して同じテストを実行し、同じ失敗が再現することを確認した。
今回の言語対応に合わせて、このテストの期待値を緩めたり、スキップに変更したりはしていない。
WASMが未配置のため、Web全体には既存のスキップも残る。

検証で実認証情報、実モデル、Cua Cloudは使っていない。
送受信検証用に開いていたモックGUIは終了せず、言語のGUI確認には別の一時HOMEを使った。
Webの既存依存はユーザーの許可後に7日間の検疫を有効にして導入し、lockfileは変更していない。
Nodeのengine警告は出たが、型検査、関連テスト、本番ビルドは実行できた。

## 追加対応の記録

追加作業では、共通カタログを312項目へ拡張し、Cua Botsのチャット、プロフィール、ルール、メモリ、ペアリング、スケジュール画面と、Web UIのAgents、Space一覧・詳細、設定画面の固定文言へ翻訳を適用した。
設定画面では、メニューバー、Spaceの既定の作成先、外観、サインイン、プライバシー説明、キーボードショートカットを追加し、環境変数名やショートカット値は挿入値として保持する。
カタログの英日キー整合、Web UIの型検査・本番ビルド、ローカライズ関連テスト、設定関連のSwiftテスト、macOSアプリのビルドは成功した。
macOS全体テストでは設定画面のスナップショット5件が失敗した。生成画像には既存の言語選択行があり、参照画像にはないため、今回追加した翻訳以外の差も含む。スナップショットの更新は行っていない。
Web全体テストは70ファイルが成功し、既知のファイル転送テスト1件が引き続き失敗した。
OxlintはWebプロジェクト内に実行ファイルが見つからず、未実施である。

## 残りの対応

全画面の翻訳は完了していない。
Space作成、端末、通知、Keyvaultなどに固定文言が残る可能性があり、引き続き画面を確認する必要がある。
ElectronとTauriは言語の実アプリ検証が未実施である。
Cua BotsとCua Spacesの別プロセス間では、設定変更の即時同期をまだ実装していない。
