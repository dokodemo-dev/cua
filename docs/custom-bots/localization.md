# 日本語表示の導入記録

## 方針

公式アプリとCua Botsに既存の言語パック機構がないため、共通の日英カタログと表示言語設定を追加した。
現在の会話で、両アプリと共有Web UIを対象に段階的に進める方針を確認した。
実モデルへの依頼文や会話履歴の言語を変える機能ではない。

実装と追加手順の正本は[`libs/cua-localization/README.md`](../../libs/cua-localization/README.md)に置く。
SwiftとWebでカタログを別々に持たず、同じJSONを参照する。
保存先は既存のBotデータやSDK設定とは分離し、RustのFFI型や生成バインディングは変更しない。

## Tauri版（`apps/cua-spaces`）の日本語化（2026-10-23）

Tauri版には独自のi18nextカタログ（`src/i18n/locales/<lng>/*.json`）と、設定画面の「言語」セレクタがある。
一方で設定画面の見出し・行・選択肢はコア（WASM）が英語で返すため、カタログだけでは日本語にならない。

`SettingsPanel` でコアの文字列を `tl()` に通す `tx()` を追加した。
キーは英語の原文そのものなので、訳がある文字列だけが置き換わり、無いものはコアの英語のまま残る。
対象はセクション名、行ラベル、補足、選択肢、ボタン、リンクの文言。
`en/settings.json` にも同じキーを英語のまま追加し、`translations.test.ts` のキー一致と用語集（`Spaces` と `Teams` は英語のまま）を満たした。

確認:

| 対象 | 結果 |
| --- | --- |
| `tsc` | 成功 |
| `vitest run src/i18n` | 26テスト成功 |
| 設定画面（同一フロントエンドをブラウザで表示） | アカウント／Teams／一般／プライバシー／AIエージェント／実験／言語、行ラベルとオン・オフ・表示・非表示が日本語 |

メインウィンドウの見出し・サイドバー（設定、検索、エージェント、通知、サインインしていません）と、エージェント・通知画面のコア文字列、Space詳細のFacts（状態・イメージ・識別子・システム）も同じ方式で訳した。

残り: ビューア（Space詳細のライブ画面・ウィンドウ一覧）とTeleportの一部。

### Privacyの表示と実効設定（2026-10-23 追記）

以前「環境で無効なのにオンと表示される」と報告したが、再確認の結果は**誤認**だった。
Tauriの設定画面を拡大して確認すると、選択枠は「オフ」側にあり、`SettingsPanel` のテストも `On: aria-checked=false / Off: true / 行は無効 / Set by env DO_NOT_TRACK` を固定している。
アプリのログも `enabled=false source_kind=do_not_track` を出しており、表示・コア・バックエンドは一致している。

## WASMコアの再生成（2026-10-22）

Web UIの判定は`cua-spaces-app-core`のWASMに依存する。未生成だと該当テストがスキップされ、画面もフォールバックで動く。
次の手順で生成した。

```sh
rustup target add wasm32-unknown-unknown --toolchain 1.97.1
cargo install wasm-bindgen-cli --version 0.2.126 --locked

export PATH="$HOME/.cargo/bin:$PATH"
RUSTUP_TOOLCHAIN=1.97.1 node apps/cua-spaces-web/scripts/build-core-wasm.mjs
```

このMacではmiseが`RUSTUP_TOOLCHAIN=stable`を環境変数で設定しており、`apps/cua-spaces/rust-toolchain.toml`の`1.97.1`より優先される。
stableには`wasm32-unknown-unknown`が入っていないため、そのまま実行すると`can't find crate for core`で失敗する。
`RUSTUP_TOOLCHAIN=1.97.1`を明示すると通る（`env -u`ではmiseのシムが再設定するため効かない）。

結果:

| 対象 | 結果 |
| --- | --- |
| `node scripts/build-core-wasm.mjs` | 成功、`core_bg.wasm` 5.0MB |
| `vitest run`（WASMあり） | 105ファイル、665テスト成功、1スキップ（従来は33ファイル・204テストがスキップ） |
| `tsc --noEmit` | 成功 |
| `vite build` | 成功、`dist`は14MB、`core_bg.wasm`を同梱 |

生成物`src/bridge/core/wasm/`は`.gitignore`対象であり、リポジトリには含めない。
CIや他の開発者も同じ手順を踏む必要がある。

## 追加対応の記録

追加作業では、共通カタログを312項目へ拡張し、Cua Botsのチャット、プロフィール、ルール、メモリ、ペアリング、スケジュール画面と、Web UIのAgents、Space一覧・詳細、設定画面の固定文言へ翻訳を適用した。
設定画面では、メニューバー、Spaceの既定の作成先、外観、サインイン、プライバシー説明、キーボードショートカットを追加し、環境変数名やショートカット値は挿入値として保持する。
カタログの英日キー整合、Web UIの型検査・本番ビルド、ローカライズ関連テスト、設定関連のSwiftテスト、macOSアプリのビルドは成功した。
macOS全体テストでは設定画面のスナップショット5件が失敗した。生成画像には既存の言語選択行があり、参照画像にはないため、今回追加した翻訳以外の差も含む。スナップショットの更新は行っていない。
Web全体テストは70ファイルが成功し、既知のファイル転送テスト1件が引き続き失敗した。
OxlintはWebプロジェクト内に実行ファイルが見つからず、未実施である。

## 残りの対応
