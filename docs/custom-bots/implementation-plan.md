# 段階的な実装計画

## Phase 1の現在地

実装済みの範囲はPiの初期選択、SDKからの選択肢取得、Bot別設定の保存、編集UI、新設定でのRun作り直しである。
Core/UIテストとアプリ全体のSwiftコンパイルで検証する。
Phase 1全体の完了とはしていない。

完了に必要な残作業は次のとおりである。

1. Rust依存を安全に用意し、`cua-spaces-ffi` をビルドしてSwift側へ配置する。
2. 隔離したHOMEと専用のローカルSpaceでアプリを起動する。
3. SDK固定版Piとローカルのモックモデルを使い、作成、送受信、同一Run継続を確認する。
4. 実行先だけにテスト用SkillとExtensionを配置し、読み込みとツール実行を確認する。
5. Codexでも同じ経路を確認する。
   Claude Codeはユーザーが再開を許可するまで呼び出さない。
6. Macアプリを再起動し、設定復元と既存Runへの再接続を確認する。
7. 上記を終えてからPhase 2の実装へ進む。

認証、課金、クラウド操作が必要になった場合は実行前に確認する。
依存の追加インストールやネイティブライブラリの取得は今回行っていない。

## Phase 2で分離する実行先

`ExecutionTarget`、`Bot.execution_target_id`、`SpaceBinding` を追加する。
既存Botは既存のplacementとspaceIDから互換レコードへ移行し、VMの作成とBotの割り当てを別操作にする。
最初は既存Spaceの選択と直接接続を実装し、VMの自動作成はSDKの既存機能に任せる。

共有Spaceでは所有権と参照数を持たせる。
Botのresetで共有Spaceを削除しないこと、停止が他Botを止めないこと、画面操作のleaseが排他になることを先にテストする。

## Phase 3で追加する接続管理

事前構築済みWireGuardネットワークの内部アドレスへ接続する。
鍵の発行やピア追加は扱わない。
接続状態は期限付きのhealth probeから更新し、失敗とオフラインを区別する。
再接続はタイムアウトと上限付きバックオフを設ける。

Bot単位の認証と認可を実装するまでは、複数Botから管理APIを使わせない。
VPNへの参加を操作権限の代用にしない。

## Phase 4で追加する協調

ハーネス非依存の管理APIにBot、Task、Message、Artifact、Groupを配置する。
Pi ExtensionはこのAPIのクライアントとする。
最大委任深度、期限、同時実行数、再送時の冪等性、ループ検出を純粋なドメインテストで確認してからツールを公開する。

最初は明示した宛先へのメッセージと単発委任に限定する。
グループ発言への全Bot自動応答は実装しない。

## Phase 5で分離するスケジューラー

現行RoutineClockを維持しながら、UIプロセス外に永続ジョブを持つ実行サービスを追加する。
再起動、実行中クラッシュ、期限切れlease、同じジョブの二重配送をテストする。
UIの終了後も実行できると報告するのは、このサービスを配置して停止再開を検証した後とする。

- 作成UIとプロファイルの編集UIを更新した。
